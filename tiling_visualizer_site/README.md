# Dynamic Tiling Visualizer Site

A web-based visualizer for Hailo dynamic-tiling benchmark runs. It plays
drone footage with frame-synced detection and tile overlays rendered on an
HTML5 canvas, and shows metrics comparison tables across run configurations.
The site is a pure static site — vanilla JS/HTML/CSS, no framework, no build
step — and can be hosted on any server that serves static files.

---

## Directory layout

```
tiling_visualizer_site/
├── README.md              # this file
├── package_site.py        # packaging: transcode + copy + manifest
├── site_config.json       # curated content list (videos, runs, trials)
├── tests/
│   └── test_package_site.py  # Python unittest for packaging logic
└── web/                   # site source (copied verbatim into dist/)
    ├── index.html
    ├── css/
    └── js/
        ├── core/          # geometry, filters, frames logic + *.test.js
        ├── state.js        # central store + URL hash codec
        ├── manifest.js
        ├── main.js
        └── ui/            # stage, overlay, runs-panel, metrics, keyboard, …
```

`dist/` is generated by `package_site.py` and is not committed to git.

## Quick start (local)

**Prerequisites:** Python 3.8+, ffmpeg/ffprobe on PATH, Node.js 20+ (for tests
only).

```bash
cd tiling_visualizer_site

# Full build: transcode source videos to 1080p H.264, copy run JSONs, emit manifest
python3 package_site.py

# Serve and open in browser
python3 serve.py            # no-cache dev server on :8123 (preferred)
# or: python3 -m http.server 8123 --directory dist
# → http://localhost:8123
```

> **Note:** `python3 -m http.server` does **not** implement HTTP Range requests.
> Video playback will work, but seeking may be degraded (the browser cannot
> fetch arbitrary byte ranges, so it may have to re-download from the start).
> Use nginx for production (see [Deployment](#deployment-to-a-hailo-server)).

### Flags

| Flag | Default | Description |
|---|---|---|
| `--skip-transcode` | off | Skip video transcoding; copy/refresh everything else. Fast for iterating on JSON data after the first full build. |
| `--out DIR` | `dist/` | Output directory. |
| `--config FILE` | `site_config.json` | Path to the config file. |
| `--repo-root DIR` | parent of `tiling_visualizer_site/` | Root for resolving relative `path` entries in the config. |

Missing input files (source videos or run JSONs) cause an immediate error with
the full list of missing paths — the build never produces a partial dist.

## Adding a run or video

Edit `site_config.json`, then re-run `package_site.py`.

### Config structure

```json
{
  "title": "Hailo Dynamic Tiling Benchmark",
  "videos": [
    {
      "id": "0025",
      "title": "DJI 0025 — baseline walkers",
      "variants": [
        {
          "fov": "fov50",
          "source": "/absolute/path/to/source_fov50.mp4",
          "runs": [
            {
              "id":    "0025_fov50_dyn_t3",
              "label": "dynamic trial 3",
              "type":  "DYN",
              "path":  "dynamic_tiling/runs/baseline_0025/frames_fov50/trial_3.frames.json"
            },
            {
              "id":    "0025_fov50_dense",
              "label": "dense 12x9 ov25 (GT ref)",
              "type":  "DENSE",
              "path":  "dynamic_tiling/runs/dense_0025/fov50/pxt_GT-12x9-25-multi.frames.json"
            }
          ],
          "trials": [
            {
              "id":    "0025_fov50_trials",
              "label": "dynamic ov0",
              "path":  "dynamic_tiling/runs/baseline_0025/trials_fov50.json"
            }
          ]
        }
      ]
    }
  ]
}
```

**Field semantics:**

- `id` — unique identifier used in URL hashes and as a filename stem in `dist/data/`.
- `label` — human-readable name shown in the runs panel.
- `type` — one of `DYN` (dynamic tiling run), `DENSE` (dense static baseline),
  or `GT` (ground-truth reference). Drives overlay colour and legend icons.
- `source` — absolute path to the source MP4. The packager transcodes it to
  browser-safe 1080p H.264 (faststart). Any path that is not absolute is
  resolved relative to `--repo-root`.
- `path` (runs/trials) — path to the frames JSON or trials JSON, **relative to
  `--repo-root`** (i.e. the repo root, not this directory).

Each `fov` variant of a video is treated as a separate playback track; the UI
lets the user switch between FOVs for the same video via the top bar.

## Deployment to a Hailo server

The `dist/` directory is fully self-contained — no Python runtime, no Hailo
stack, no database. Copy it to any host that can serve static files.

Once all source videos are transcoded, `dist/` is dominated by the MP4 files
(approximately 200–400 MB for 4 videos at 1080p H.264 CRF 22). Verify with
`du -sh dist/` after a full build.

### Option A — nginx (recommended for production)

nginx serves HTTP Range requests by default, which enables smooth video
seeking.

Minimal server block:

```nginx
server {
    listen 80;
    server_name tiling-viz.internal.hailo.ai;

    root /var/www/tiling-viz;

    location / {
        try_files $uri =404;
    }

    # Optional: compress JSON (run data can be several MB)
    gzip on;
    gzip_types application/json text/plain text/css application/javascript;
}
```

After configuring nginx, deploy with rsync (see Option C below).

### Option B — quick share behind the firewall

```bash
python3 -m http.server 8080 --directory dist
```

This is suitable for demos over the internal network. Be aware that
`python3 -m http.server` does **not** support HTTP Range requests — video
seeking may be degraded (playback from the start always works). For a shared
team deployment, use nginx instead.

### Option C — rsync one-liner

```bash
rsync -av --delete dist/ <server>:/var/www/tiling-viz/
```

Replace `<server>` with the target hostname or SSH alias. The `--delete` flag
removes stale files when you re-package with updated runs.

## Deep links

The URL hash encodes the current viewer state and is updated as you navigate,
so any view is shareable:

```
http://host/#v=<videoId>&fov=<fov>&runs=<id,id,...>&f=<frame>&conf=<0.30>
```

| Parameter | Example | Meaning |
|---|---|---|
| `v` | `0025` | Video ID |
| `fov` | `fov50` | FOV variant |
| `runs` | `0025_fov50_dyn_t3,0025_fov50_dense` | Comma-separated enabled run IDs |
| `f` | `312` | Frame number |
| `conf` | `0.30` | Confidence threshold |

Copy the browser URL at any point to share an exact frame and run selection.

## Keyboard shortcuts

Active in Viewer mode. Ignored while a text input is focused or a
platform modifier (Cmd/Ctrl) is held.

| Key | Action |
|---|---|
| `Space` | Play / pause |
| `[` / `]` | Step one frame back / forward |
| `Home` / `End` | Jump to first / last frame |
| `f` | Reset zoom and pan |
| `+` / `-` | Zoom in / out |
| `1` – `8` | Toggle run visibility (manifest order); `Alt+N` = solo that run |
| `t` | Cycle tile source through runs that have tile data |
| `p` | Toggle hide-phantoms filter |
| `m` | Toggle containment-merge filter |
| `,` / `.` | Playback speed down / up (0.25×, 0.5×, 1×, 2×, 4×) |
| `g` | Open go-to-frame prompt |
| `?` | Open / close keyboard shortcuts overlay |

## UI guide

**Runs panel** — Each run has an eye icon (click to toggle visibility), a
colour swatch (click to cycle through the palette), and a tile-source radio
button that controls which run's tile grid is drawn on the canvas. Alt-clicking
the eye icon solos that run (hides all others).

**Filters** — Three controls in the filter panel:

- **Confidence threshold** — slider; detections below this score are hidden.
- **Hide phantoms** — removes detections that appear only inside tile overlap
  regions (likely duplicate detections from adjacent tiles).
- **Containment merge** — suppresses a smaller detection that is fully
  contained within a larger one from the same run (reduces duplicate boxes).

**Inspector** — Hovering a detection on the canvas highlights it in the
right-rail inspector, which shows per-run detection counts for the current
frame (shown, phantoms, merged). Clicking a detection locks the hover.

**Metrics mode** — Switch via the top-bar mode toggle. Shows a summary table
per run: chip-level statistics, per-cell recall heatmaps, and best-of-N stars
across trial sets. A "Copy as Markdown" button copies the table for pasting
into reports.

## Testing

### JavaScript (32 tests)

```bash
node --test tiling_visualizer_site/web/js/**/*.test.js
```

Requires Node.js 20+. Tests cover geometry math, phantom/containment-merge
filters, frames-JSON indexing, and the end-to-end filter pipeline.

### Python packaging (unittest)

```bash
cd tiling_visualizer_site
python3 -m unittest discover -s tests -v
```

Tests cover config validation, manifest construction, and the ffprobe CSV
parser without invoking ffmpeg.
