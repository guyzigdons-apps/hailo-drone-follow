Address RSIM-05 ("`install.sh --rover` installs apt packages: `ros-humble-ros-base`, `ros-humble-geometry-msgs`, `ros-humble-ros-gzgarden-bridge` (NOT `ros-humble-ros-gz-bridge` which is Fortress). Purpose: This is the single entry point for a fresh contributor to install rover-sim deps. It must:
1. Not regress existing behavior — without `--rover`, `install.sh` does exactly what it did before.
2. Fail friendly when `apt-get` is missing (`exit 6`) — not silently no-op.
3. Fail friendly when the osrfoundation apt repo is not configured (`exit 7`) — and print the exact `curl` + `tee` commands to add it. The dev box has Harmonic (gz-sim8) installed; a contributor running `install.sh --rover` on Harmonic will hit this exit-7 path and follow the README's Harmonic-substitution recipe (per Plan 05-03).
4. Verify `gz` CLI ends up on PATH after the install (`exit 8`) — a final sanity check.
5. Pin the EXACT apt package names: `ros-humble-ros-base`, `ros-humble-geometry-msgs`, `ros-humble-ros-gzgarden-bridge`, `gz-garden`. NOT `ros-humble-ros-gz-bridge` (Fortress; a real package name typo that breaks rover-sim silently per PITFALLS Pitfall 5).

This plan runs in Wave 2 with one explicit dependency: Plan 05-03 (README) must land first so the README's "Quick start" command `sudo ./install.sh --rover` matches the flag delivered here. The dependency is a contract / documentation alignment, not a code dependency — both files could technically land in any order, but ordering 05-04 after 05-03 makes the README's claim true at the same HEAD that introduces it.

Plan 05-04 can run **in parallel** with Plan 05-05 (`start_rover_sim.sh`) — both touch disjoint files (`install.sh` vs `sim/rover/start_rover_sim.sh`).

Output: A single file modification at `install.sh` (~50 lines of added code: flag parse + step block + preflight checks). Verification is structural (grep, shellcheck) + invocation tests (`./install.sh --rover` on a stripped PATH to assert friendly exits 6/7/8 fire correctly).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `install.sh` (operator-invoked, runs as root via `sudo` for apt) ↔ apt package universe | `install.sh --rover` calls `sudo apt-get install -y` with a hard-coded list of package names. | osrfoundation apt repo ↔ system trust store | The `apt-cache search` preflight check assumes the operator has already added the osrfoundation repo via the gazebo.gpg signing key. The check is a soft-fail with helpful instructions (exit 7); it does NOT auto-add the repo (that would be a silent supply-chain expansion). |
| `gz-garden` apt package ↔ Gazebo Harmonic on the same machine | A box running Harmonic (gz-sim8) installing Garden (gz-sim7) ends up with both libgz-* trees. They coexist on disk but the wrong one may be linked at runtime. README documents the Harmonic-substitution recipe; install.sh does NOT auto-detect Harmonic (RESEARCH Q3 lock — single-target Garden for v1.1; auto-detection doubles the test matrix). |
