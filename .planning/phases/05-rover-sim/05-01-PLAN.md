<objective>
Create `sim/rover/rover.sdf` — the differential-drive rover model with a forward-facing camera and the Garden-era `gz::sim::systems::DiffDrive` plugin. Address RSIM-01 (Garden-era plugin names + camera sensor) and RSIM-02 (`<topic>cmd_vel</topic>` topic override so `ros_gz_bridge` maps ROS `/cmd_vel` ↔ gz `/cmd_vel`).

Purpose: This SDF is the spawnable Gazebo model that subsequent world files (Plan 05-02) and the launcher (Plan 05-05) consume. It locks in two pitfall mitigations from PITFALLS.md:
- **Pitfall 5 (silent load failure):** Use `gz::` prefix and `gz-sim-diff-drive-system` filename — NOT `ignition::`. The `ignition::` prefix produces a silent load failure on Garden: Gazebo starts, no error, `/cmd_vel` is ignored.
- **Pitfall 6 (topic namespace mismatch):** Override the default `/model/rover/cmd_vel` with `<topic>cmd_vel</topic>` so the bridge can map `/cmd_vel ↔ /cmd_vel` cleanly without model-name knowledge.

Camera parameters (1280×720 @ 30 Hz, hfov 1.152 rad ≈ 66°) match the drone x500_vision convention verbatim so the same Hailo pipeline tile-cropper configuration and ByteTracker tuning carry over between drone-sim and rover-sim runs.

This plan is autonomous, runs in Wave 1, and can run **in parallel** with Plan 05-02 (worlds) and Plan 05-03 (README) — all three touch disjoint files. No Python is added in this plan; the entire `robot_follow/` tree must remain byte-identical to HEAD.

Output: A single SDF file at `sim/rover/rover.sdf` (~100–140 lines). Verification is structural (grep) + optional `gz sdf -k` skip-on-no-gz lint. Full E2E "rover actually rolls" verification is **Phase 6 RINT-04**, not this plan.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rover.sdf (file on disk) ↔ Gazebo Garden gz-sim loader | Garden parses SDF and loads named plugins by `.so` filename. Wrong filename or wrong plugin name → silent load failure (Pitfall 5). |
| DiffDrive plugin ↔ gz-transport13 broker | Plugin subscribes on the topic named in `<topic>` (or `/model/<name>/cmd_vel` default). Mismatch between bridge config and plugin subscription → cmd_vel silently dropped (Pitfall 6). |
| Camera sensor ↔ gz-transport13 broker | Camera publishes raw image on `<topic>` (default `/<sensor>/image`). `video_bridge.py` (UNCHANGED) subscribes on the configured topic and forwards via H.264 RTP to UDP 5600. |
| UDP 5600 (downstream of `video_bridge.py`, not this plan) | Unauthenticated UDP — anyone on the same host loopback / LAN can sniff or inject video. Mitigation: `video_bridge.py` defaults `--host 127.0.0.1` (loopback only) — verified at `sim/bridge/video_bridge.py:40`. |
