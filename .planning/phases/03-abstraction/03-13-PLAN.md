**Architectural decision (recorded in must_haves.truths and inline in the do_POST patch):**
The leniency widening triggers ONLY when `len(available_ids) == 1`. Rationale:
1. Single-available is the ONLY case where operator intent is unambiguous — there is exactly one person on screen, and the operator clearly meant to lock onto them regardless of which (now-stale) id the React closure captured.
2. Zero-available has no candidate to recover onto — keep 404 + tell the operator no person is visible.
3. Multi-available (e.g., `{45, 67}`) is ambiguous — recovering to "the first one in iteration order" would silently lock onto the wrong person; better to return 404 and let the operator re-click the (now-fresh) bbox they want. Fix shape #2 (position-based) would resolve this case but requires UI + SSE schema changes — explicitly deferred per 03-12-SUMMARY.
4. The recovery log is INFO (not DEBUG) so the operator sees in the scrollback that the server auto-recovered onto a different id — important for trust + future debugging.

**Threat surface (per `<threat_model>` block below):**
`FollowServer` binds to `host="0.0.0.0"` by default (see `robot_follow/servers/follow_server.py:142` and call site `robot_follow_app.py:448`). The endpoint is reachable from any device on the local network when the air unit is on a Wi-Fi AP (typical field deployment). This plan WIDENS server-side leniency by exactly one case, so it slightly enlarges the attack surface for "an attacker on the local network can lock the drone onto an arbitrary visible person by sending any int". Mitigation: the operator-only threat model is unchanged — this endpoint had no auth before this plan and still has none; the existing single-available case (operator clicks → server locks onto the only visible person) was already trivially reachable by any local-network actor with a single curl. The new behavior expands "any id resolves to that single person" by ONE additional case: stale id submitted in the same situation. Net new attack capability: zero (an attacker could already POST `/follow/45` directly if 45 is the only available id). Disposition: ACCEPT (no auth added in this plan; this is operator-local field-ops trust boundary).
