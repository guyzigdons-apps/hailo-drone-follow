```bash
cd /home/<user>/code/<user>/hailo-drone-follow
```

```bash
drone-follow --takeoff-landing --webui --input udp://0.0.0.0:5600
```

Expected at startup:
- Console banner shows offboard handshake messages: "[MAVSDK] Connection: udp://...", "[MAVSDK] Connected", "[MAVSDK] Holding setpoints for offboard activation", "[MAVSDK] Offboard mode activated"
- Web UI accessible at http://localhost:5001 with live MJPEG stream
- Drone arms + takes off to target_altitude (3 m default)

**Step 3 — Observe target-follow (5+ minutes):**
- The actor walks across the field, then approaches the drone
- Verify:
  1. **Drone faces the actor** — yaw tracks actor position. As actor moves left, drone yaws left; as actor moves right, drone yaws right.
  2. **Drone maintains target bbox height** — when actor walks AWAY, drone moves forward (closing distance). When actor walks TOWARD, drone moves backward (retreat-from-tilt + emergency safety as bbox grows).
  3. **Altitude held at ~3 m** — drone doesn't drift up/down significantly (P controller working).
  4. **Smooth motion** — no jerky setpoints; EMA smoothing visible as gradual velocity changes in the web UI's velocity readout.
  5. **No "stuck" behavior** — drone doesn't hold zero setpoints when actor is in frame (would indicate orchestrator state machine got stuck in search-mode).
  6. **No NaN / clamping artifacts** — control loop log shows clean numbers, no warnings about NaN forwards or excessive yawspeed.

**Step 4 — Compare to pre-Phase-3 baseline (if accessible):**
- If the operator has a recording or memory of pre-Phase-3 SITL behavior on the same world, mentally diff: is the follow quality the SAME? If a regression is observed (drone overshoots, oscillates more, loses target where it didn't before, altitude drifts more), THAT'S a Phase 3 BUG to surface.

**Step 5 — Ctrl+C clean shutdown:**
- Press Ctrl+C in Terminal 2
- Expected: drone lands cleanly (since --takeoff-landing was passed); MAVSDK server reaper fires; no stuck zombie processes (`pgrep mavsdk_server` empty 5 s after exit)

**Step 6 (optional — ROS env-leak verification, ROS-equipped boxes only):**

- `ROS_DISTRO=humble` added
- `AMENT_PREFIX_PATH=/opt/ros/humble` added
- `LD_LIBRARY_PATH=/opt/ros/humble/lib:...` appended (venv libs come first)
